# Orchestrator architecture diagnosis

## Current audit flow

1. **Application discovery.** `discover_project()` walks a bounded set of manifests and source paths and records framework, styling, testing, and integration signals. `build_project_intelligence()` separately parses HTML and source text to infer routes, components, imports, and design tokens. The isolated benchmark was the only project directory passed to either pass.
2. **Source evidence.** The Codex path creates a temporary, symlink-free source snapshot, omits `.agents`, credentials, binary files, and project instruction files, installs the bundled specialist TOMLs in that snapshot, then places included and skipped file paths in the prompt metadata.
3. **Application startup.** `--url` only attaches to a server that is already running. `--start-command` is a separate interactive, typed-confirmation path that starts an argument vector without a shell. For this benchmark, the explicitly requested static server was started separately and the audit attached to loopback.
4. **Route selection.** Without `--route`, `renderable_route_candidates()` passes statically inferred route paths to the browser. Repeated `--route` values select exact paths. Dynamic routes are excluded, but the inferred paths were not normalized before selection.
5. **Screenshot capture.** `capture_screenshots()` visits every selected path at each viewport in the requested depth. Deep mode is 1440×1000, 768×1024, and 390×844. It records readiness, HTTP status, console/page/request errors, DOM and controls, computed styles, and navigation timing; it saves PNGs, a JSON manifest, and an HTML gallery. A passive first-Tab screenshot may add one image per route.
6. **Screenshot delivery.** `run_codex_audit()` passes every captured screenshot path as a repeated `--image` argument to every specialist invocation. The minimal integration check confirmed the Codex CLI received and interpreted a real 1440×1000 dashboard image. In the baseline audit, route validation aborted capture before any image existed, so no image was sent.
7. **Specialist calls.** Three sequential role-specific tasks run for technical, behavioral, and visual review. Each successful first pass is followed by a second evidence-check pass. The visual task is skipped when there are no screenshots. Specialist TOML files are copied into the temporary snapshot, while the backend invokes the default Codex agent with a role prompt; it does not select a specialist using a CLI `--agent` flag.
8. **Structured output.** Hand-authored dictionaries define the response JSON Schemas. `codex exec --output-schema` enforces them; a local recursive validator checks the returned JSON and later finding/evidence references are validated against snapshot files and screenshots. The schemas allow absent `line` and `viewport` evidence keys, which the installed Codex strict-output interface rejects because all object properties must be listed in `required`.
9. **Finding consolidation.** The orchestrator validates finding fields and evidence, merges static runtime signals with model findings, deduplicates records, and preserves recommendations and limitations. Static HTML sink rules currently emit one generic finding per source occurrence without tracing callers or inputs.
10. **Reports.** `reporting.py` renders separate technical, behavioral, visual, and summary documents. `intelligence_reports()` adds architecture, route, component, token, responsive, runtime, and coverage artifacts. Reports are stored under `.agents/frontend-design-director/reports/`, with an additive numbered audit revision.
11. **Execution failures.** The backend collapses Codex stderr to the last three non-empty lines and 500 characters. The audit coordinator truncates caught specialist exceptions again to 240 characters and stores them as report limitations. Browser capture exceptions are caught around the whole route/viewport batch; one bad inferred path therefore suppresses successful captures and no per-route failure manifest is written.
12. **Completeness.** There is no explicit completed-with-limitations/incomplete/failed status. Once report generation finishes, the state machine transitions to `AUDIT_COMPLETED` even if all model specialists failed or the visual task was skipped. The result labels `codex_cli_plus_static` based on the requested backend, not successful specialist execution.

## Baseline diagnosis

- The source route parser treated relative links such as `../analytics` as path strings relative to the source file and emitted paths such as `/analytics/../analytics`. `capture_screenshots()` correctly rejected traversal, but the exception escaped the route loop and aborted all captures. Baseline: 26 route candidates, 0 rendered routes, 0 screenshots, and the visual auditor was not invoked.
- The installed binary was editable-linked to this checkout. Its pipx Python environment did not contain the optional Playwright package. The host Python environment did contain Playwright 1.65.1 and installed Chromium, so the baseline CLI module was run with the same checkout on that host interpreter without changing pipx. Route validation failed before browser launch in that run.
- Codex 0.167.1 successfully interpreted a single attached screenshot with a strict minimal schema. The production `FINDINGS_SCHEMA` failed before producing a model result. Full redacted stderr is preserved in `benchmark-results/baseline/diagnostics/codex-schema-findings.stderr.redacted.txt`; the service reported `invalid_json_schema` because `schema.properties.findings.items.properties.evidence.items.required` omitted the `line` property. This confirms a JSON Schema incompatibility, rather than an authentication or image-format failure.
- The baseline technical report contains three repetitive HTML-injection warnings, while code and UX specialists failed and visual analysis was skipped. The audit nevertheless reports backend `codex_cli_plus_static` and transitions to the completed phase. These are demonstrated coverage and status defects, not merely report-writing weaknesses.

## Evidence boundary

The audit pipeline reads only the isolated `demo-app` copy. Baseline reports, JSON output, source hashes, and the one-image smoke-test screenshot/response were frozen under `benchmark-results/baseline/` before evaluator-private files were opened. No evaluator-private content was included in the project snapshot or model prompt.
